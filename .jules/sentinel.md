## 2024-05-24 - Buffer Overflow in Rconnection::login
**Vulnerability:** A critical heap buffer overflow and potential segmentation fault exists in `Rconnection::login` within `Rconnection.cpp`. `authbuf` is allocated with a fixed size `strlen(user)+strlen(pwd)+22`, but `crypt(pwd, salt)` can return strings up to 86 characters (e.g., SHA-512 hashes), leading to an overflow. Also, `crypt` could return `NULL`, causing `strcpy` to segfault.
**Learning:** The buffer size calculation assumed `crypt()` would return an old DES-style hash (13 chars) and did not account for larger modern hashes or potential error returns. This mismatch between allocated size and dynamically generated content length causes buffer overflows.
**Prevention:** Always verify `crypt()` return values for `NULL`. Compute required buffer sizes dynamically *after* determining the actual output length of cryptographic functions. Use safer functions like `snprintf` or allocate buffer lengths exactly matching `strlen(hash_output) + 1`.
