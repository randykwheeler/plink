## 2024-05-01 - Buffer Overflow in crypt() Authentication
**Vulnerability:** A heap buffer overflow existed in `Rconnection.cpp:login()` where `authbuf` was sized based on the length of the plaintext password (`pwd`) plus 22 bytes, but then populated using the output of `crypt()`. Since modern implementations of `crypt()` return hashes of varying lengths (e.g., SHA-512 hashes can be 106 characters long), this routinely exceeded the allocated memory buffer, especially for short passwords.
**Learning:** Never assume the length of cryptographic function outputs matches the length of the inputs. Memory must be dynamically allocated *after* determining the actual length of the hash. Additionally, functions like `crypt()` can return `NULL` (e.g., malformed salt), requiring explicit checks to avoid null pointer dereferences (segfaults).
**Prevention:** Calculate the required buffer size by calling `strlen()` directly on the `crypt()` output. Always test that `crypt()` return value is not `NULL` before performing length calculations or string copy operations. Allocate only after all dynamically sized components are known.
