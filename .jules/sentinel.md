## 2025-02-13 - [Heap Buffer Overflow in Rconnection Login]
**Vulnerability:** A heap buffer overflow vulnerability in `Rconnection.cpp` where `authbuf` was allocated a fixed size `strlen(user)+strlen(pwd)+22`, but the result of `crypt(pwd, salt)` could exceed 22 characters, leading to memory corruption. Furthermore, `crypt` return value was not checked for NULL, causing potential null-pointer dereference in `strcpy`.
**Learning:** `crypt()` output length is algorithm-dependent and often exceeds traditional short hashes (e.g., SHA-512 hashes can be 100+ bytes). Fixed-size offset allocations are inherently dangerous when dealing with dynamic crypto outputs. Additionally, library calls like `crypt` and memory allocators like `malloc` must always be null-checked before usage.
**Prevention:** Always dynamically determine buffer sizes based on the *actual* output length of security primitives (e.g., `strlen(crypt_output)` instead of fixed paddings). Always perform strict `NULL` checks on allocator and library function returns before dereferencing.
